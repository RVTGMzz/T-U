# Team Up! v0.1 alpha.4 - Party Core Milestone

## Goal

Alpha.4 should turn the current party/follow prototype into a usable Party Core before combat systems are added.

The milestone focuses on **stability, party management, and shared storage**.

## Phase 0 - Alpha.3 smoke test

Before adding alpha.4 features, build and test the current alpha.3 code in-game.

Required checks:

- project compiles successfully;
- SMAPI loads `Ronvotri.TeamUp` without errors;
- NPC can join the party;
- party cap counts only Party Members;
- player main pet does not consume a Main Party slot;
- Follow / Wait / Resume work repeatedly;
- map transitions do not duplicate or lose followers;
- save/reload preserves party state;
- old alpha save migration does not create duplicate pets/companions;
- no stale dialogue/menu lock after party commands.

If alpha.3 fails any core test, fix that before Party Vault UI work.

## Phase 1 - Leave Party

Implement a proper Leave Party action.

Acceptance criteria:

- Party Member is removed from active party data;
- Linked Companion deployment is cleaned up with the owner;
- NPC is safely released back to vanilla schedule/behavior;
- save data updates immediately;
- repeated invite -> leave -> invite cycles do not duplicate state.

## Phase 2 - Party Vault Core

**Party Vault remains a permanent Team Up! feature.**

The first implementation should prioritize data safety over automation.

Alpha.4 Vault requirements:

- one shared Vault per player/team context;
- safe save/load persistence;
- item stacks preserved;
- quality preserved;
- metadata/modData preserved where the game serialization path supports it;
- no follower auto-consumption yet;
- no auto-loot yet;
- clean failure handling for unsupported/modded items;
- controller-friendly opening path prepared.

Do not reduce the Vault to a list of item IDs if that would discard item-specific data.

## Phase 3 - Minimal Party Panel

Create the first Team Up! management UI.

The initial panel should display:

```text
TEAM UP!

MAIN PARTY                     4 / 6
Alex         Tank       Following
Abigail      DPS        Following
  └ Companion Unit     Active
Emily        Support    Following
Harvey       Healer     Following

COMPANIONS                     1 / 2
Player Pet                     Active
Linked Companion               Active

[ Party Vault ]
[ Manage Member ]
[ Close ]
```

Alpha.4 does not need the final visual design.

It does need:

- keyboard navigation;
- mouse navigation;
- controller navigation;
- clear focus states;
- Main Party count separate from Companion Unit deployment count;
- access to Party Vault;
- member selection for Wait / Resume / Leave Party.

## Phase 4 - Linked Companion UI state

The Party Panel must be able to represent:

- no linked companion;
- linked companion available but Standby;
- linked companion Active;
- player main pet as a separate free companion;
- active Linked Companion limit reached.

Automatic Pelipper Town / Pokemon detection is **not required for alpha.4**.

The adapter/API layer should come later after the provider mod's real data model is verified.

## Phase 5 - Validation pass

Alpha.4 is considered ready when the following loop is stable:

```text
Invite NPC
-> Follow
-> Wait
-> Resume
-> Change map
-> Open Party Panel
-> Open Party Vault
-> Save
-> Reload
-> Leave Party
-> Invite again
```

Test this with:

- one NPC;
- four NPCs;
- six NPCs through config;
- player main pet;
- a mock/manual Linked Companion record where practical.

## Explicitly out of scope for alpha.4

Do not add these until Party Core is stable:

- threat/aggro;
- Tank/DPS/Support/Healer/Control combat AI;
- Signature Abilities;
- damage/healing balance;
- auto-loot;
- follower auto-consumption;
- final Codex UI;
- SVE/Ridgeside combat packs;
- Pelipper Town live integration.

## Next milestone after alpha.4

If alpha.4 is stable, alpha.5 or v0.2 prototype can begin the **Combat Foundation**:

- combat eligibility;
- target acquisition;
- Engagement Style;
- leash and retreat logic;
- basic Role behavior;
- threat/aggro prototype;
- one small vanilla test roster before expanding to every NPC.
